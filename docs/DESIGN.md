# FallbackAuction — 拍卖履约托管与违约递补协议（设计稿 · 待核对）

> Monad Blitz@广州 · eventId=18 · 目标网络 Monad 测试网（chainId 10143）

## 1. 定位

不做现场出价演示，专攻往届拍卖都没覆盖的**成交后履约**：保证金托管、超时违约罚没、第二高价递补、流拍退款，全部由合约按链上时间自动执行。

对应场景：实物 / 法拍 / 域名 / RWA 等链下结算拍卖——付款走链下、交付走链下，链上只管保证金、出价排序、违约判定与递补顺序。标的先用数字 URI 占位。

## 2. 关键参数

| 参数 | 含义 | 示例值 |
|---|---|---|
| `itemUri` | 标的标识（字符串 / 哈希） | `ipfs://...` 或描述哈希 |
| `startPrice` | 起拍价 | 10 MON |
| `minIncrement` | 最小加价幅度 | 1 MON |
| `bidDeadline` | 出价截止时间（timestamp） | 部署后 30 分钟 |
| `payWindow` | 中标付款窗口（秒） | 600 秒 |
| `depositRatio` | 保证金占出价比例 | 10% |
| `maxBidders` | 单场出价人数上限（gas 安全） | 8 |

## 3. 状态机（七状态）

```
OPEN ──settle()──▶ PAYING ──pay()──▶ WON（成交，款清，beneficiary 提款）
                       │
                       │ payWindow 内未付款
                       ▼
                   DEFAULTED ──advanceFallback()──▶ FALLBACK
                                                       │
                                                       │ 下一名进入付款窗口
                                                       ▼
                                                    PAYING（递补轮）
                                                       │
                                                       │ 无人承接
                                                       ▼
                                                    ABORTED ──▶ REFUNDED
```

状态枚举：`OPEN`、`PAYING`、`WON`、`DEFAULTED`、`FALLBACK`、`ABORTED`、`REFUNDED`。

## 4. 资金规则

- **`bid(price)`**：发送 `deposit = price × depositRatio` 进入合约托管；记录 `(bidder, price, deposit, block)`。同一出价人可加价，保证金差额补足。
- **`settle()`**：出价截止后任何人可调；取最高价为当前中标人，进入 `PAYING`。
- **`pay()`**：中标人付尾款 `price − deposit`；到账后 `WON`，标的链下交付，价款由 `beneficiary` 提取。
- **违约判定**：`payWindow` 内未 `pay()` → 当前中标人违约，其保证金**全额罚没给 beneficiary**，进入递补。
- **`advanceFallback()`**：任何人可调，**每次只向下推一名**（gas 安全，不遍历全榜）；下一名成为新的待付款中标人，开启新的付款窗口。
- **流拍**：候补名单无人承接 → `ABORTED`；未违约者保证金全额退还；违约者保证金已罚没。
- **退款**：未中标者、流拍候补者退还全额 deposit。

## 5. 资金分布表（纸面核对）

示例：`depositRatio = 10%`，出价 A=100（保证金 10）、B=80（保证金 8）、C=60（保证金 6）；beneficiary = 发布者。

### 路径一：A 违约 → B 成交

| 角色 | 出价 | 保证金 | 尾款 | 最终支出 | 标的 |
|---|---:|---:|---:|---:|---|
| A（违约） | 100 | 10 罚没 | 0 | 10（罚没给发布者） | 否 |
| B（递补成交） | 80 | 8 抵价款 | 72 | 80 | 是 |
| C（未中标） | 60 | 6 全额退还 | 0 | 0 | 否 |
| 发布者 | — | 收 10（A 罚没）+ 80（B 全部价款：保证金 8 + 尾款 72）= **90** | | | 售出 |

### 路径二：A、B 都违约 → 流拍

| 角色 | 出价 | 保证金 | 最终结果 |
|---|---:|---:|---|
| A（违约） | 100 | 10 罚没给发布者 | 支出 10 |
| B（违约） | 80 | 8 罚没给发布者 | 支出 8 |
| C（候补未成交） | 60 | 6 全额退还 | 支出 0 |
| 发布者 | — | 收 **18** 罚没；标的未售出，链下退回 | |

> 罚没规则为可调参数；演示版默认违约保证金全额归 beneficiary。

## 6. Gas 安全

- `maxBidders = 8` 硬上限。
- 排名在插入 / 加价时维护为有序数组；递补每次调用只移动一名指针，**禁止 while 循环遍历全榜**。

## 7. 明确不做（范围外）

防狙击延时、AI 出价建议、荷兰式降价、撤价、争议仲裁治理、实物交付、观众钱包 onboarding。

## 8. 演示脚本（3 个脚本钱包）

- 场景一：A 出价最高后不付款 → 链上标红划掉 → B 递补成交。
- 场景二：A、B 均违约 → 流拍 → C 退款。

## 9. 前端（只读最小页）

出价榜（排名 / 金额 / 保证金 / 状态）、当前中标位、违约标红、递补链路、退款状态；接测试网 RPC，`newHeads` 订阅 + 回执轮询。

## 10. 上链理由（pitch 口径）

- 出价托管、超时判定、递补顺序、退款：链下做需信任运营方，合约自动执行且事后可查。
- Monad 侧只讲：低费让多轮递补操作不心疼；**不把快出块 / 低延迟写进上链理由**（拍卖周期按小时/天算）。
